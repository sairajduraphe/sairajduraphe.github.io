Product work, end to end

The tools are the visible part. The product work behind them is what I do every week.

Discovery

I spot where the team loses time: sheets rebuilt by hand, imports that fail, files nobody can place.

Requirements

I turn know-how that lives in people's heads into written rules, like a 14-rule pipeline and a 42-column sheet spec.

Cross-team delivery

PXM import console

In internal use

One web app for API imports, bulk uploads and exports, replacing a command-line script.

Problem
Imports, uploads and exports depended on a script and manual steps. Only technical people could run them safely, and a wrong run was hard to undo.
What I built
All five import types with a dry run before anything is applied, a three-step bulk upload, exports, and admin-managed access.
Product decision
I found two things the API can't do yet, writing image-stack order and mapping across channel templates. I filed both as feature requests instead of building fragile workarounds.

Flat-file converter

Live internally

Turns Amazon template exports into import-ready sheets by drag and drop.

Problem
Reshaping each file by hand was slow, and one shifted row or column could corrupt a whole import.
What I built
A 14-rule pipeline that finds header rows from the file itself, handles every product-category tab, and keeps each value in its own row. Known data fixes live in a file anyone can edit.
Evidence
Measured on real files at about 20 to 25 seconds for roughly 1,000 products. It went live on company infrastructure through a reviewed pull request, my first full deploy.

Shopify sheet generator

In internal use

Builds a 42-column Shopify import sheet from one platform export.

Problem
A brand's sheet was built by hand from many hidden rules, and I was its only owner for over a year. That's a risk for the team.
What I built
A tool and written spec that groups variants into families, resolves shared attributes, sorts sizes in the brand's cycle and adds image-only overflow rows. Missing source data goes to a QC tab instead of being invented.
Evidence
I found and fixed five bugs. A sample run produced 803 rows from 725 variants plus 78 overflow rows.

AI failure triage

Prototype

An n8n and Claude workflow that diagnoses app failures and asks me before any fix.

Problem
With several internal apps running, failures reached me late and without context.
What I built
A workflow that checks one private channel every five minutes, has Claude diagnose a failure report, and tags me for approval. Nothing changes without my yes.
Design choice
Trust came first: a human approves, scope is one channel, and the apps escalate only when a user can't fix it themselves.

73,000 files to 1,320 products

Delivered

Matching a brand's asset library to its product folders by SKU.

Problem
A library of 73,091 files had no clear link to the 1,320 product folders they belonged to.
What I built
A tiered matcher: an exact variant if the filename names one, then the default, then the only one that exists. Anything ambiguous goes to a review list instead of a guess.
Evidence
About 36% matched with confidence and about 6% went to review. I caught two errors myself: files in the wrong folder, and counts that disagreed between the workbook and the summary. Both were fixed.

How I run a product

The same five steps every time, each with a real artifact behind it.

  1. Scope

    Find the task that repeats and the person who suffers from it.

    A written problem statement

  2. Spec

    Write the rules until edge cases are explicit, including what the tool must refuse to guess.

    A rules document

  3. Build

    Use AI to draft, then run it on real files and compare with what I know is right.

    Tested on real data

  4. Ship

    Host it, control who can use it, and make failures visible.

    A reviewed pull request

  5. Iterate

    Fix what users hit, and send engineering what the tool can't solve.

    Bug fixes and feature requests
